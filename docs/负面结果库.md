# 负面结果库 · Negative Results Registry
> 定位：**A 号产出物之二**。负面结果同样是知识 —— 这里登记"已经试过、确实不行/未证实"的假设，
> 附**实验编号、数据、判据**。目的是让别人（和未来的我们）不用重跑同一条死路。
> 记录规则：①必须有可复现命令 ②必须写清"否掉的是哪个具体假设"（不是含糊的"效果不好"）③必须区分**证伪**与**未过关**。

## NR-1 「新模块用零初始化挂载，等价性 100% 就说明改造无损」— **证伪**
- **假设**：结构等价测试通过 ⇒ 改造安全。
- **反例**：N1/S0 首版：等价性 100.00%，但 `gate` 恒为 0 的分支**从未被激活**，活体测试（gate→1.0）一致率崩到 98.11%（应等于"有意义地改变输出"），且 `∂L/∂gate = 0` —— **零死锁**。
- **教训**：等价性对死锁是**盲的**。必须等价性 + init 梯度体检**同做**。
- **修正**：`V`/`w_out`/`q_proj` 必须非零；只允许最后一层 `gate` 零初始化。
- **复现**：`code/memstate_s0.py`（失败）vs `code/memstate_s0b.py`（修正后通过）；工装 `init_grad_health`。

## NR-2 「用抽样 hash 校验主干是否被改动」— **证伪（仪表不可信）**
- **假设**：对主干张量按固定步长抽样、拼字节求 hash，前后比对即可证明主干未变。
- **反例**：N2b 报 `主干 ❌ 被改动`；N2c 换成**张量级全量 max-abs-diff**后为 **0.000e+00** ⇒ 是**仪表假警报**。
- **教训**：验证"没变"必须全量比对；抽样 hash 只能作快速探测，**不得作为"未改动"的证据**。
- **复现**：`code/memstate_n2b.py`（抽 hash）vs `code/memstate_n2c.py`（张量级）；工装 `trunk_invariance`。

## NR-3 「训练样本可以带上下文内事实」— **证伪（实验设计错误）**
- **假设**：训练时喂「事实：K 的编号是 V。\n问：K 是什么？\n答：V」能训练记忆分支。
- **反例**：N2 首版：loss 2.85→0.70 看似学到，**召回 0%** —— 模型直接**抄上下文**，记忆分支成摆设。
- **教训**：评估记忆必须用**查询式**（上下文无事实，唯一通路是记忆）。
- **复现**：`code/memstate_n2.py`（有错）vs `code/memstate_n2b.py`（查询式）；工装 `train_query_style`。

## NR-4 「用留出键评估静态记忆的写入能力」— **逻辑不可能**
- **假设**：留出键（训练时未写入）的召回率可以衡量写入能力。
- **反例**：静态池里**根本没有**那条关联 ⇒ 该指标理论上恒为 0，它只能当**负对照**，不能当写入能力指标。
- **教训**：静态写入的正确指标是**训练键**的召回率；留出键的作用是抓"瞎猜蒙对"。
- **复现**：`code/memstate_n2b.py` / `n2c.py` 的留出键栏位。

## NR-5 「小样本 + 单种子可以下结论」— **证伪（本项目被骗过一次）**
- **假设**：N2c 报"记忆分支 + 读出侧 = 训练键精确召回 9.4%（vs 无记忆对照 3.1%）"⇒ 记忆分支有效。
- **反例**：N2d 放大到 **128 键 × 2 种子**后，记忆臂 **0.0% / 0.0%**，无记忆对照 **0.0% / 2.1%** ⇒ **净贡献 −1.0 pp**。9.4% 是 n=32 单种子的噪声。
- **教训**：小样本差异必须放大；`RunRecord.single_seed_warning` 强制标注。
- **复现**：`code/memstate_n2c.py`（n=32）vs `code/memstate_n2d.py`（n=128×2 种子）。

## NR-6 「只训 0.3% 架构件 + 冻结主干，就能把知识写进记忆表」— **本机预算下证伪**
- **假设**：新增记忆分支（可训参数 ≈ 0.3%，主干冻结）即可建立关联记忆的写入与读出。
- **反例**：
  - 静态池：N2d 记忆臂净贡献 **−1.0 pp**（无正贡献）；多深度注入（每 4 层）同样 **0.0%**。
  - 动态写入：N2e（Titans 式，写入=内部梯度步）训练键/留出键 exact 召回 **0.0%**，loss 曲线 4.73→**8.30**→3.54（不稳）。
- **边界**：N2e 属**"实现未过关"**（长可微链 + 无梯度裁剪 + lr 偏大 + 240 步 ×BS=4），**不能据此说原理被证伪**；但**实用结论明确**：本机预算下此路不通。
- **对标**：Memory Layers（Meta，1T token）与 Sparse Upcycling（~50% 原始预训练预算）均为**大规模联合训练**；**业界无"冻结主干 + 小模块"档位的成功先例**。
- **复现**：`code/memstate_n2d.py`、`code/memstate_n2e.py`；报告 `N2_报告.md` §6–§8。

## NR-8 「必须做到与原模型逐位一致（bit-exact）才算改造成功」— **过度要求（作者定调撤销）**
- **原判据**：S0 要求同设备逐位 100%（token 一致率 + logits maxdiff == 0）。
- **作者定调（2026-09-24）**：**「不一定要 token 一致，因为是自我进化的」** —— 本架构本身会写入/巩固/改写权重，
  "与原模型逐位一致"只是搬运旧参数阶段的诊断工具，不是项目目标。
- **实测支撑**：挂零门旁路（gate 恒 0、数学上贡献为 0）后，全位置 logits 仍出现 **9.0e-05** 漂移、
  token 一致率在不同调用结构下于 **79%–100%** 摆动 —— 根因是 cuBLAS 在模块结构变化后选不同核，
  **属核级数值差，与改造是否有功能副作用无关**。
- **修订后判据**：**功能等价 = 全位置 logits max-abs-diff ≤ 1e-3**（教师强制）+ token 一致率 ≥ 确定性底线；
  bit-exact 降为**可选取证**（需 `CUBLAS_WORKSPACE_CONFIG=:4096:8` + `torch.use_deterministic_algorithms(True)`）。
- **复现**：`tools/memcore_harness.py --selftest`（六项全过，`harness-ok`）。

## NR-9 工装自测抓出的三个真实缺陷（**已修，记录以防复现**）
| # | 缺陷 | 症状 | 修复 |
|---|---|---|---|
| 1 | `ProductKeyMemory.forward` 返回 `(out, sel)` 元组 | 与门控相乘时 `gate * tuple` → `TypeError: only integer tensors...` | 只返回张量，`sel` 存 `self.last_sel`（审计用） |
| 2 | 主干快照过滤器写成 `"_branch."` | 漏掉真实模块名 `mlp.branch.*` ⇒ 把自己刚挂的架构件当"主干"，误报 **主干被改动 6.0e-05** | 过滤器改为 `.branch/.mem./.gate/.A/.B` 特征，且**快照必须在注入之前取** |
| 3 | 基线 logits 指纹 `prompt_ids + gen` | `gen` 已含 prompt ⇒ 序列被拼两次 ⇒ 比出 **maxdiff 4.0e+01** 的假警报 | 只拼续写段 `prompt_ids + base_tokens[p]` |

**教训**：**工装自己也要做自测**——这三个缺陷全部是"自测第一次跑"就暴露的，若不跑自测，它们会变成实验里的假结论。
- **现象**：N2c 报峰值 **13.45 GiB > 12 GiB 物理显存**，数值自相矛盾。
- **处理**：该数字**一律不引用**；改用 `SMISampler`（`nvidia-smi` 1Hz 独立采样）交叉验证。
- **状态**：待用新口径重测（工装已就绪）。
