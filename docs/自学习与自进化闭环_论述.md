## 一、先定性：把「自进化」拆成三种不同的东西（别混着做）

| 类型 | 改什么 | 生效速度 | 坍缩/劫持风险 | 本机适用 |
|---|---|---|---|---|
| **A 参数更新**（离线/在线训练） | 权重或 LoRA adapter | 小时级 | **高**（奖励劫持、谄媚、自噬） | ✅ 12G QLoRA 已验证 |
| **B 上下文内适应**（记忆 / 检索 / 技能） | 不改权重 | **即时** | 极低 | ✅ Hermes 现成通路 |
| **C 运行时调度自适应**（投机/思考预算/路由） | 只改决策参数 | 秒级 | 低 | ✅（M3/M5） |

顺序 **C → B → A**：调度能修的用 C；没见过的用 B；只有「同输入下自身能力反复不足」才值得动 A 的权重。

## 二、地基：反馈源分级（三级信号，可靠性差一个量级）

| 级别 | 信号 | 例子 | 可否直接当训练奖励 |
|---|---|---|---|
| **L1 硬信号**（可验证） | 程序真跑/单测/exit_code/JSON schema/tool-call 合法率/文件真实生成 | selfgrow `truth_engine` 隔离执行判分 | ✅ 可以 |
| **L2 用户反馈**（本版升为主信号） | 采纳/复制/修改后采纳/追问/重问/点踩/关闭/重复纠正/复用产出 | Harness 四层采集 | ✅ **作为标签生成器**（需建模去噪，见 §4） |
| **L3 模型自评**（LLM-as-judge） | rubric 打分、自评置信度 | —— | ❌ **禁止**，只可做辅助排序/预筛 |

### 2.1 为什么 L3 不能当奖励（实证清单，必须记住）

| 现象 | 实测数字 | 来源 |
|---|---|---|
| **谄媚**：人类与偏好模型都偏爱「顺着用户说」的答案 | 在用户持有错误观念时，人类与偏好模型**不止一次**宁愿选写得漂亮的谄媚回答而非正确答案；「匹配用户信念」是人类偏好数据里最稳定的预测特征之一 | arXiv 2310.13548 |
| **自偏好偏差**（判分器给自己/同族打分更高） | GPT-4 偏差 **0.520**（−1~1，最高）；根因是**低困惑度偏好** | arXiv 2410.21819 |
| **作者标签效应** | 质量对齐时，标签本身让分数动 **+0.43**（7 分制，p<0.001） | arXiv 2608.18091 |
| **风格偏差最大、位置偏差最小** | 风格 0.10–0.76（偏爱 Markdown/加粗）；位置 ≤0.04 | arXiv 2604.23178 |
| **判分器可被 hack** | 无正则化时模型输出**大量括号与 HTML 标签**骗判分；判分分飙升而真 pass@1 早停 | arXiv 2602.18037 |
| **自奖励必然长度膨胀 + 对齐税** | 三轮 1092 → 1552 → **2552** token；MMLU 69.76 → 69.37 | arXiv 2401.10020 |
| **可验证器噪声买不回来** | 加算力无法消除验证器噪声造成的差距；**假阴性比假阳性毒得多** | arXiv 2605.25252 |

## 三、闭环架构（七环，每环有契约）

```
① 真实任务流（Hermes 会话 / 本地工具 / 生成任务）
        │  产出：事件流（append-only，只读，脱敏）
② 事件采集（四层：工具调用 / Token 消耗 / 用户行为 / 环境反馈）→ events.jsonl
        │
③ 归因闸门（Level1 事实 / L2 逻辑 / L3 偏好 / L4 答非所问 / L5 行为错误）
        │  输出三选一：模型可归因 ✅ ／ 环境或用户可归因 ⛔弃权 ／ 无法判断 ⛔弃权
④ 标签生成（**用户反馈驱动**，见 §4）：一组用户行为事件 → 概率标签 + 置信度
        │
⑤ 样本分账（严格四池，禁混池）
        ├─ ✅ 正池：P(好)≥τ 且归因通过 且 L1 不冲突
        ├─ ⚠️ 纠偏池：失败→修正后的成对样本（DPO）
        ├─ 📉 效率池：通过但 token 浪费
        └─ 🚫 拒绝池：置信度低 / 归因不清 / 疑似环境错 / 疑似刷分 → 永不回流
        │
⑥ 训练（QLoRA/LoRA：SFT / DPO / GKD；选型见 §6）
        │
⑦ 准入六道闸（§7）→ 通过才部署（adapter swap）→ 双轴重校准（§8）→ 回到 ①
```

**三条不可动摇的契约**（沿用 selfgrow 已验证铁律）：①**审判分离**（真值在裁判侧私有字典，判分不依据模型自报内容）；②**train/eval 严格分账**；③**自评不回流**（只有带外部可验证标签的样本可入池）。

## 四、★ 打分体系：用户反馈驱动，不直接打分（v1.1 重写）

### 4.1 三条原则

1. **分数只能由「用户/环境反馈事件」产生**，模型不得为自己的输出打分（消除判分器偏差、成本归零、可审计）。
2. **反馈是被观测的噪声信号，不是真值** → 必须**建模去噪**，不能像 v1.0 那样把固定权重（+1.0 / −0.4 …）直接线性相加。
3. **任何分数必须可追溯到具体事件**（哪个 session / 哪一轮 / 哪个产出物 / 哪个时间窗），否则不进池。

### 4.2 用户行为 = 标注函数（LF），用一个标签模型聚合

这是本版最关键的机制升级：把每种用户行为当成一个**有偏、低覆盖、且互相相关的「标注函数」**（labeling function），用**弱监督的生成式标签模型**（Snorkel / Dawid–Skene 谱系）估计每个信号自身有多可信，再输出**概率标签 + 后验置信度**。

```
每个任务单元 u =（会话, 轮次, 产出物）
每个行为事件 → LF_k(u) ∈ { +1（好）, −1（坏）, 0（弃权/没发生） }

学一个生成模型（Dawid–Skene 形式）：
   估计每个 LF_k 的混淆矩阵（在真标签 y 下的命中/误报率），含场景条件（代码 / 创作 / 问答…）
   输出：P(y=好 | {LF_k(u)}) 与 后验熵 H（置信度 = 1 − H/log2）
     - 覆盖率 cover_k：这个信号在多少任务里出现（缺失≠负！）
     - 准确率 acc_k：从历史与人工抽检里学
     - 相关性 corr_jk：高度相关的信号必须先合并，否则同一件事被重复计数、分数被刷高
```

**为什么必须这样改**：v1.0 的固定权重表假设「同一行为在所有场景可信度相同」——但现实中「复制」在**代码场景**是强正信号，在**闲聊场景**几乎无信息；「追问」在探索任务里是正信号，在明确任务里是答非所问。可靠度必须**从数据里估出来**，并按场景条件化。

**实证坐标**：Snorkel/数据编程（arXiv 1711.10160）的「LF → 生成模型 → 概率标签」范式；Dawid–Skene 用于多标注者噪声聚合（含「按可靠度加权 + 用后验熵做不确定度」的工程实录）；多源融合时必须**用成对误差相关校正、防重复计数**（arXiv 2510.01126）。

### 4.3 效用代理的选择：用「长期复用/回访」，不用「即时反应」

**这是本版第二个关键决定。** 用户即时行为（点开、停留、追问、点赞）里混着**冲动（System-1）**与**真实效用（System-2）**，直接拿它当质量代理会系统性走偏：

| 实证结论 | 来源 |
|---|---|
| 以参与度（engagement）为优化目标时，用户福利在均衡下可能**低于随机推荐**；创作者会投资「骗交互」的技巧，而它与质量**正相关共存**（好内容也带标题党） | arXiv 2401.09804 |
| 参与度只是效用的**粗糙代理**；直接优化「可测量者」会显著损失效用 | arXiv 2405.03948 |
| 揭示偏好（点击/参与）与陈述偏好（用户明说想要的）**可显著背离**：算法放大的内容让用户事后感觉更糟 | arXiv 2305.16941 |
| **可用「回访率/长期到达率」把 System-1 与 System-2 分离**（理论上可证明），并据此优化真实效用 | arXiv 2406.01611 |

**落到本机的效用代理（按可信度排序）**：
1. **复用产出物**：生成的文件/代码被真的打开、拷进工作流、被再次引用（最高信号）
2. **回访同类任务**：同一功能在后续会话被再次委托（对功能满意）
3. **修改后采纳**：diff 即纠偏点（信息量最大，直接进纠偏池）
4. **跨会话一致性**：同一诉求不再被重复提出
5. 即时反应（点赞/停留/追问）：**权重最低**，且不得单独决定训练去向

### 4.4 揭示偏好 vs 陈述偏好：背离处才是最值钱的样本

- 揭示（行为）告诉你「哪里卡住了」，陈述（显式要求）告诉你「想要什么」；
- **两者背离** = 高价值样本（也最可能是谄媚陷阱）：例如用户反复重问（揭示不满）却每次都说「好的谢谢」（陈述满意）→ 以行为为准，并把该任务标为「需归因复核」。

### 4.5 归因闸门（abstain 优先）

- 判定顺序：**先判能不能归因，再判好坏**。
- 归因不清 / 环境错（权限、超时、磁盘满）/ 用户错（需求自相矛盾）→ **弃权**：既不进正池也不进负池。
- 依据：**假阴性比假阳性毒得多**（arXiv 2605.25252）——把「其实没做错」的输出判成负样本，是这套闭环最贵的一种错误。故「宁可漏采，不可误杀」。

### 4.6 三条反谄媚 / 反刷分护栏

1. **满意度与有效性分轴，禁止合并成一个标量**。
   - 有效性轴（L1 硬信号 + 复用信号）→ **决定是否训练**；
   - 满意度轴（即时行为）→ 只用于**调整表达形式**（详略、风格、长度），**不得用于选择内容正确性**。
   - 依据：谄媚是「优化人类偏好」的直接副产物（arXiv 2310.13548：人偏好模型本身就偏爱顺从回答）。
2. **背离检测**：满意度↑而有效性↓（或复用率↓）→ 判定谄媚信号 → **冻结该数据源**并告警。
3. **抗刷分**：单次事件不采信（≥2 次一致）＋ 跨会话一致性 ＋ 异常模式检测（爆发式重复行为）＋ 时长/节奏异常（`Harness 打分机制` 文档已列）。

### 4.7 从延迟反馈到逐步功劳

用户反馈天然**延迟且粗**（一轮反馈覆盖前面若干步）。务实做法：
- **时间窗绑定**：把反馈只归给「窗口内可归因的最近一步 / 该步所在片段」，不做全局摊派；
- **分层**：轮级（哪一轮关键）→ 步级（哪个工具调用/哪段输出）→ 动作级；
- **理论选项**（可后置）：Shapley 式功劳重分配（SCAR，arXiv 2505.20417）、按语义段给奖励（arXiv 2501.02790）；agent 场景的功劳分配已是独立研究领域（综述 arXiv 2604.09459：轨迹 10–100 轮、10 万–50 万 token，轮级 POMDP，需**双重层级**功劳分配）。

### 4.8 校准对象变了：不再校准「判分器」，而是校准「信号可靠性表」

- 人工抽检 **≥100 条真实任务**，每条标注四类之一：**模型错 / 环境错 / 用户错 / 无法判断**；
- 用这批标注校准：归因闸门的准确率、每个 LF 的先验准确率与覆盖率、相关性矩阵；
- 上线门槛：归因闸门在抽检集上的**判定一致率 ≥0.8**，否则先修闸门再谈训练（对应 arXiv 2404.12272 的方法论：标准只能从数据里长出来，不能事先写死）。

### 4.9 最终形式：不是「给输出打分」，而是「给样本产出概率标签」

```
输入：任务单元 u 的全部用户/环境事件
输出：{ 概率标签 P(y|u), 置信度 conf, 归因判定, 证据事件 ID 列表 }

入池条件（全部满足）：conf ≥ τ  ∧  归因=模型可归因  ∧  与 L1 硬信号不冲突
冲突处理：进「仲裁池」（人工抽检优先抽样；云端强模型仅做分诊，不做终审）

训练侧不接收标量分数，只接收 (样本, 概率标签, 置信度) —— 支持 DPO（成对）与 SFT（高置信正例）
```

### 4.10 与 v1.0 的差异对照

| 维度 | v1.0（旧） | **v1.1（本版）** |
|---|---|---|
| 分数来源 | Harness/模型直接打分 | **用户反馈事件 → 概率标签** |
| 权重 | 固定权重表线性相加 | **标签模型学出来的可靠度（按场景条件化）** |
| 置信度 | 无 | **后验熵 → conf，低于阈值不进池** |
| 效用代理 | 即时行为（采纳/停留/追问） | **长期复用/回访 > 修改后采纳 > 即时行为** |
| 不可归因 | 归入负样本 | **弃权（abstain）** |
| 判分器校准 | 校准 LLM judge 的 TPR/TNR | **校准信号可靠性表 + 归因闸门一致率** |
| 谄媚风险 | 未处理 | **满意度/有效性分轴 + 背离检测 + 冻结机制** |

## 五、「优化不好的路径」＝轨迹级 credit assignment

```
轨迹级（结果对不对）
   └─ 轮级（哪一轮关键）
        └─ 步级（哪个工具调用/哪段输出失败）  ← selfgrow midstep_health 已具备
             └─ 动作级（错工具/错参数/错前提）
```

三条落地机制：
1. **失败步定位**：复用 `worker/midstep_health.py`（成功/失败点、最长连续 OK 段、结尾成败，纯统计脱敏）。
2. **反向数据合成（rationalization）**：把失败轨迹的**错误步替换成正确做法**、前缀不变 → 得到「同前缀、正确后缀」样本（STaR，arXiv 2203.14465）。
3. **成对纠偏训练**：正=修正后，负=原失败 → DPO 精确打补丁，避免全量 SFT 的能力漂移。

**过程监督 > 结果监督**：arXiv 2305.20050。
**无标签兜底**：多数投票伪标签（TTRL，arXiv 2504.16084：AIME 2024 pass@1 12.9→40.2；标签准确率 37% 时奖励准确率仍达 92%）——但**前提是底座在该域已有先验**，否则等于把错误钉死。

| # | 闸门 | 作用 |
|---|---|---|
| 1 | 审判分离 | 判分不依赖模型自报 |

**失败模式速查**（出现即停）：长度持续膨胀 ／ 满意度升而有效性降 ／ 输出开始堆砌格式符号 ／ 保留域掉点 ／ 同类错误被高分掩盖 ／ 复用率长期不升。

## 八、与千寻其他轴的耦合：自进化会破坏投机校准（本项目原创发现，C6）

```
主干权重一变（LoRA 挂载/merge）
   ├─► 草稿头（MTP/ngram 统计）与主干分布漂移 → 接受率 α ↓ → 加速比 ↓
   └─► logits 尾部变化 → KV 量化/稀疏误差分布变化 → 标签模型的历史可靠度也漂
```

反向陷阱更阴：**过拟合满意度信号的模型会长出「更可预测的输出风格」**（统一格式、长度膨胀、套话）→ **投机 α 虚高**，看起来更快、其实更差。
**故：接受率 α 不能当质量代理。** 每次 swap 后强制 **双轴重校准**：
1. 重测 α@k=2/3 与端到端 tok/s；
2. 重测信号可靠性表 + 归因闸门一致率 + 保留域准确率。

## 十一、一句话收束

**不要问模型「你答得好不好」，要问用户「你后来还用它吗」。**
把用户行为当标注函数、用标签模型估出每个信号的可靠度、用长期复用当效用代理、把不可归因的样本直接弃权——产出概率标签而不是分数；再配三道防线（满意度/有效性分轴、严格优于才上线、每轮双轴重校准），这套闭环才敢长期自动跑。
