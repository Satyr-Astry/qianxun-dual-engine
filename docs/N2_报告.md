## 0. 结论摘要（诚实版）

| # | 结论 | 证据 |
|---|---|---|
| 1 | **主干可以做到严格零改动** | 三个实验臂的**张量级最大改动 = 0.000e+00** ✅（训练 250 步后逐参数比对） |
| 2 | **"只训记忆分支 + 冻结主干"不足以建立可读出的关联召回** | Arm3（只训记忆分支）：训练键**精确召回 0.0%**、数字级 6.2% |
| 3 | **读出侧（下游层 + LM head）才是瓶颈** | 加读出侧后：Arm1（记忆+读出侧）**精确 9.4%** vs Arm3 **0.0%**；loss 5.38→0.79 vs 5.09→1.20 |
| 4 | **记忆分支有正向边际贡献，但当前统计不显著** | Arm1（有记忆）9.4% exact vs Arm2（无记忆、纯读出侧）**3.1%** exact —— 32 条样本即 3 条 vs 1 条，**方向正向但样本量太小（n=32、单种子），不能下结论** |
| 5 | **负对照干净**：模型没有"瞎猜蒙对" | 三臂的**留出键召回一律 0.0%**（训练键与留出键是不同生造词） |
| 6 | **仪表教训**：抽样 hash 会假警报 | N2b 用的"抽样 hash 校验主干"报了 ❌ 被改动；N2c 换成**张量级 max-abs-diff** → **0.000e+00**，证明主干确实没动，是仪表坏了 |

**对本项目的意义**：S0（结构无损）已坐实；但 **S1「只训架构件」不够**——记忆要能被"读出来"，必须让读出侧（末几层 + LM head）一起进入训练。这条直接改写 N2/N4 的路线。

## 1. N2（首版）：两个实验设计错误（有价值的失败）

| 观察 | 数值 | 归因 |
|---|---|---|
| loss 大降 | 2.85 → 0.70（200 步） | ❌ 假进步 |
| gate 长起来 | 0 → 0.089 / 0.102 / 0.134 | 分支确实被激活 |
| 留出键召回 | 精确 0.0% | —— |

**错误 1（抄近路）**：训练样本形如「事实：K 的编号是 V。\n问：K 的编号是什么？\n答：V」——
**事实就在上下文里**，模型只需"从上下文复制"，`loss` 下降与记忆分支无关。
**错误 2（评估口径错）**：静态记忆池里**根本没有留出键的条目**，用留出键评"写入能力"在逻辑上不可能为正；
留出键只能作**负对照**。正确评估对象是**训练键**（写得进→读得出）。

---

## 2. N2b（修正）：查询式训练 × 四组单变量

训练格式改为**查询式**（`问：K 的编号是什么？答：V`，上下文无事实）⇒ 唯一通路就是记忆分支。

| 组 | 配置 | loss | 训练键（32 条）精确 / 数字级 | 留出键 | 主干 |
|---|---|---|---|---|---|
| A | 居中×3，gate 从 0 | 4.72 → 4.45 | 0.0% / 0.0% | 0.0% | 校验 ❌（仪表坏） |
| B | 居中×3，gate 热启 0.05 | 4.84 → 4.36 | 0.0% / 0.0% | 0.0% | ✅ |
| C | 靠后×3（近 LM head） | 4.65 → 4.62 | 0.0% / 0.0% | 0.0% | ❌（仪表坏） |
| D | 居中×3 + **LM-head LoRA** | 4.51 → **1.24** | 0.0% / **12.5%** | 0.0% / 6.2% | ❌（仪表坏） |

**读法**：A/B/C 的 loss 几乎不降（4.4–4.7 徘徊）⇒ 冻主干时记忆分支**学不动**；
D 加上 head LoRA 才把 loss 压下去，但**只学到"输出一个四位数"的表面形式**（数字级 12.5%，精确 0%），
且留出键也开始动（6.2%）⇒ 说明它在"猜格式"，不是"查表"。

## 3. N2c（决定性三臂对照）：读出侧是瓶颈

| 臂 | 配置 | 可训参数 | loss | 训练键 精确 / 数字级 | 留出键 | 主干 max-diff |
|---|---|---|---|---|---|---|
| **Arm1** | 记忆分支（居中×3）**+ 读出侧**（LM-head LoRA + 末 4 层 q/v LoRA） | 106.25M | 5.382 → **0.790** | **9.4%** / 21.9% | 0.0% / 0.0% | **0.000e+00** ✅ |
| **Arm2** | **纯读出侧对照**（同样 LoRA，**无记忆分支**） | 2.77M | 5.508 → 0.839 | 3.1% / **43.8%** | 0.0% / 0.0% | **0.000e+00** ✅ |
| **Arm3** | 只训记忆分支（N2b 最优 B 复现） | 103.48M | 5.086 → 1.198 | **0.0%** / 6.2% | 0.0% / 0.0% | **0.000e+00** ✅ |

**三条可下的判断**：
1. **读出侧必需**：Arm3（0%）→ Arm1（9.4% exact）说明"记忆分支单独存在时，下游冻结层读不出它"。
2. **记忆分支的边际贡献方向为正但弱**：Arm1 9.4% vs Arm2 3.1%（32 条 → 3 条 vs 1 条）。
   ⚠️ **样本量与种子都不够**（本项目铁律：跨种子统计断言、不靠单次结果）⇒ 记为"方向性发现，待 N2d 放大"。
3. **负对照干净**：三臂留出键全部 0.0% ⇒ 无"蒙对"污染。

**遗留疑点（未解释，必须标注）**：峰值显存统计报 **13.45 GiB > 12 GiB 物理显存**，
说明统计口径（或驱动回退/共享内存）有问题，下一轮需用 `nvidia-smi` 独立采样核对，不可直接引用该数字。

|---|---|---|

## 5. 下一步（N2d，已按本次结论改写）

| 项 | 设计 | 判据 |
|---|---|---|
| 1 | **读出侧纳入 S1 标准配置**：LM-head LoRA + 末 K 层（K∈{4,8}）LoRA | 训练键 exact 召回显著高于 Arm2 对照 |
| 2 | **放大统计**：训练键 128 条、留出 64 条、**3 个随机种子** | 三臂差异在多种子下同向且 >2σ |
| 3 | **多深度注入**：每 4 层注入一个记忆分支（不只 3 层） | 对比单点注入的召回提升 |
| 4 | **更难/更易的任务刻度**：把 4 位数改成 2 位数（更易）与 6 位数（更难），找能力边界 | 画出"任务难度 vs 召回"曲线 |
| 5 | **动态写入（Titans 式）**：把"写入"从梯度训练改成**推理时更新记忆模块** | 这是 N4 的前置；静态池只能记"训练时写进去的" |

## 6. N2d（放大统计 + 多深度 + 难度刻度）：**N2c 的 9.4% 是噪声**

| 组（均含读出侧） | seed | 训练键 exact | 数字级 | 留出键 | 主干 max-diff | 可训参数 |
|---|---|---|---|---|---|---|
| R1 记忆居中×3 | 0 / 1 | **0.0% / 0.0%** | 6.2% / 6.2% | 0% | 0.0e+00 | 106.25M |
| R2 **无记忆**（纯读出侧对照） | 0 / 1 | 0.0% / **2.1%** | 12.5% / 4.2% | 0% | 0.0e+00 | 2.77M |
| R3 多深度注入（每 4 层） | 0 | **0.0%** | 8.3% | 0% | 0.0e+00 | 106.25M |
| R4 记忆 + **2 位码**（更易） | 0 | **6.2%** | 0.0% | 0% | 0.0e+00 | 106.25M |

- **记忆分支净贡献（R1−R2）= −1.0 pp ⇒ 无正贡献**（在 128 键、2 种子、含读出侧的设置下）
- **自纠错：N2c 报的 9.4% 是噪声**（n=32、单种子），放大到 128 键 × 2 种子后归零 ⇒ 项目铁律"单次种子不可作结论"再次被实测验证
- 唯一亮点：**R4（2 位码）拿到 6.2% exact** ⇒ 难度刻度方向正确（更短的目标更容易被记忆分支产出），但仍极弱
- 主干不变性：**6 轮全部 0.0e+00** ✅（这条稳定成立）

## 7. N2e（Titans 式运行时动态写入）：**未打通**

设计：写入阶段喂「记住：K 的编号是 V。」→ 各注入层记忆矩阵做**内部梯度步**更新 `M ← (1−α)M − θ·∇ℓ(M;x)`；
读取阶段用 M 前向读出；**留出键在推理时才写入**（训练时从未见过）——这才是"写入即生效"的真考验。

| 指标 | 结果 |
|---|---|
| 基线（gate=0 旁路） | 0.0% |
| loss 曲线 | 4.73 → **8.30** → 5.95 → 5.19 → 3.54（**不稳定，先恶化**） |
| 训练键（写入即问） | exact **0.0%** / 数字级 9.4% |
| **留出键（推理时才写入）** | exact **0.0%** / 数字级 0.0% ← 核心指标未达标 |
| 负对照（不写入直接问） | 0.0% / 0.0%（干净） |

**判定**：优化本身没跑稳（长可微链 + 无梯度裁剪 + lr 偏大 + 240 步 × BS=4 远不足），
属于**"实现未过关"**——既不能据此说原理成立，也**不能说原理被证伪**。但结合 N2d，实用结论清楚：
**在本机预算（1.5B 冻结主干 + 百万级可训参数 + 几百步）下，"记忆写入→读出"没有被打通。**

## 8. 阶段结论与路线分叉（N2 全系列结账）

### 8.1 稳定成立的（可写进论文）
1. **S0 结构等价改写可行且严格无损**：逐 token 100.00%、logits 差 0.000e+00（N1）。
2. **"写入只进记忆、不进主干"工程成立**：N2c/N2d/N2e 共 9 轮训练后，主干张量 max-diff 全为 **0.000e+00**。
3. **一套可复用的实验工装**：双格式训练陷阱、留出键负对照、张量级主干不变性验证、init 梯度体检、`nvidia-smi` 独立显存口径。

### 8.2 被否掉的假设
- ❌ **"只训 0.3% 架构件 + 冻结主干"就能把知识写进记忆表** —— 静态池（N2d：净贡献 −1.0pp）与动态写入（N2e：0%）双双未过。
- ⚠️ 对标提醒：**Memory Layers（Meta）与 Sparse Upcycling 都是大规模联合训练**（1T token / ~50% 原始预训练预算），
  **业界没有"冻结主干 + 小模块"这个档位的成功先例** ⇒ 本项目原先的省算力期望需要下调。

### 8.3 四条路线（请作者圈定）
| 选项 | 内容 | 本机可行性 | 建议 |
|---|---|---|---|
| **A 降级定位（推荐）** | 项目定位改为「架构设计与机制验证平台」；产出 = 机制论文（含**负面结果**）+ 工装 + 可复现实验 | ✅ 完全可行 | ⭐ 首推：负面结果同样是知识，且诚实可发表 |
| B 外部算力 | 找云 GPU / 社区协作做真正的 S1/S2 联合训练 | ❌ 本机不可行 | 若要产出可用模型，这是唯一路径 |
| C 回到过渡工具链 | 重回 v1.4 已被本机验证的 ngram / MTP 头 / KV q8 / 调度（能立刻拿到 1.2–1.8×） | ✅ 已验证 | 想快速拿到"能用的收益"就走这条 |
| D 继续啃动态写入 | 修优化：梯度裁剪、lr 扫描、多步写入、写入/读取同构前缀、更大写入端口 | ⚠️ 研究性质，回报不确定 | 只在 A 的框架内做，别当产品 |

**小悠的判断**：A + C 组合最务实——**C 拿收益，A 拿知识**；B 需要外部资源；D 改成 A 的实验子项。
