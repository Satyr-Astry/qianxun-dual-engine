## 0. 定位（**v3.0 修正 —— 这是全书的纲**）

### 0.1 现在是什么
**这是一个「架构设计与机制验证平台」，不是「要产出可用模型的项目」。**
触发原因（实测，见 §8.4）：N2d/N2e 实测否掉了「冻结主干 + 0.3% 架构件就能写入记忆」这条最省路线；

**业界无「冻结主干 + 小模块」档位的成功先例** ⇒ 省算力期望必须下调。

### 0.4 原定位留档（v2.0–v2.3 的目标，已被 §8.4 下调）
**造一个新架构**：把「知识」从「每 token 必须扫一遍的显存权重」搬到「按需查表的分层记忆体」，把「上下文」从「越用越贵的 KV 缓存」换成「相关性召回的记忆页」，把「学习」从「一次性预训练」换成「静默期持续巩固」——**主干沿用 Qwen3-14B / DeepSeek-R1-Distill-Qwen-14B 的参数做初始化，新增的架构件只占主干参数的 0.3%**，其余靠结构改写 + 分阶段继续训练把它「活」过来。

**三个结构性收益（都是架构级，不是调参级）**：
| 收益 | 机制 | 本机数字 |
|---|---|---|
| 知识容量与显存**解耦** | 记忆条目稀疏激活（top-k 查表），参数放 DRAM/磁盘 | 8M 条目记忆库 ≈ 84 GiB（放盘）↔ 显存依旧只放 9 GiB 主干 |
| 每 token 访存**降两个数量级** | dense FFN 每 token 必须读完 **127.5 MiB/层**；记忆查找只读 top-8 条 = **80 KiB/层** | **≈1632×** 的访存差 → 12GB 机的解码天花板被从根上抬高 |
| 长上下文成本**与长度解耦** | 远端召回 = 按相关性取 top-k 页（不是滑窗、不是全 KV） | 128K 时每步读 0.62 ms 而不是 39.7 ms |

## 1. 为什么这必须是「新架构」，而不是给旧模型加模块

判定标准（主人立的规矩）：**只加模块 = 打补丁；换骨架 = 重构。**

| 维度 | v1.4「推理栈」（打补丁） | **v2.0「忆态架构」（换骨架）** |
|---|---|---|
| 记忆 | KV cache（越用越贵，是与计算绑定的副产物） | **分层记忆体**（L0 寄存 / L1 温 / L2 冷，一等公民，可写可审计可编辑） |
| 上下文 | 窗口 + 稀疏取舍 | **双通道激活**：本地滑窗（流畅）+ 远端相关性召回（长程） |
| 知识 | 全在权重里 | **权重（慢）+ 记忆条目（可扩、放盘）** |
| 学习 | 只离线 | **测试时写入 + 静默期巩固**（快权重） |
| 自进化 | 外挂闭环 | **架构内生的记忆写入与巩固** |
| 加速手段 | 投机解码等外挂技巧 | 访存结构本身改变（**1632×**），技巧变成补充 |

**为什么 27B/35B 才是对的实验台**：
1. §7.1 的核心论证是「dense FFN 每 token 必须读完 127.5 MiB/层」——**4B 模型的 FFN 太小，这个瓶颈在它身上根本不成比例**；
2. Qwen3.8-27B 有 **64 层**（48 linear + 16 full），足够做「前/中/后三段注入扫描」并对齐 MSA 的结论；
3. 35B-A3B 是 **MoE**：权重总量大、激活便宜 ⇒ 本机既跑得动，又能验证"记忆查表替代 dense FFN 访存"的收益方向；
4. 两者的 **config 都带 MTP 层** ⇒ 官方投机加速可实测（路线 C）。

**扩展基准（本机放不下，仅登记）**：Qwen3.5-122B-A10B（Q4 ≈ 65–70 G）、Qwen3.8-2.4T-A95B、DeepSeek-V4-Flash（Q4 ≈ 142 G）。

### 1A.3 新基底对架构书的四个硬性影响（**必须改设计**）

1. **MTP 头现在官方自带** 🎉
   Qwen3.5/3.6/3.8 与 V4 的 config 里都有 MTP 层（`mtp_num_hidden_layers=1` / `num_nextn_predict_layers=1`）。
   ⇒ 路线 C（过渡工具链）里的"自造 Medusa 多头"**作废**，改为**直接用官方 MTP 头做 draft**。
   （与此前实测吻合：ollama 的两个 blob 里 `nextn` 张量命中为 0 ⇒ 是**打包时被剥离**，不是模型没有。）

2. **长上下文成本已被新基底解决，本架构的差异化必须重写**
   3:1 混合线性注意力（Qwen3.5 系）与 CSA+HCA（DeepSeek V4）已经把"装得下 / 每步不变慢"做进架构。
   ⇒ 本架构**不再主张**"让长上下文变便宜"（那是它们的功劳），**只主张**：
   **记忆的「可写入 / 可编辑 / 可审计 / 可回滚 / 可自进化」**——这正是 §0 定位与 A 路线论文的落点。

3. **注入深度要从"居中"改到"后半段"（自我修正，有实证）**
   MSA（2603.23516）明确报告：**早期层的隐状态缺乏高层语义抽象，路由在那里无效**，因此它们**只在模型后半段层启用检索路由**。
   ⇒ 直接解释了我们 N2/N2d 的失败（居中 3 层注入、召回 0%）。
   **新规范：注入点取 `layers[⌈2L/3⌉ … L-1]` 区段**，并在 N6 里做深度扫描验证。

4. **记忆体形态要升级为「混合槽 + 门控 + 柔性写」（三篇 2026 新论文给了现成答案）**
   - **MoME（2609.15126）**：把每个 token 的单行记忆换成 **M 个槽的混合** + 由隐状态学的门控 ⇒ 解决"同一表面形式塌缩成一个条目"（多义词问题）。
   - **ARM（2609.24417）**：**Gumbel-Softmax 选槽** + **sigmoid 门控柔性写**（软混合替代硬驱逐）+ **自适应 top-M**（把检索预算当 MDP）⇒ 修掉我们静态池"硬查表、无写回"的毛病。
   - **Memory-Managed Long-Context Attention（2606.28876）**：**冻结 8B/14B 主干** + 学习式写入器 + **硬生命周期（覆写/保护/驱逐 ≤32 槽）** + **校准回退**。
     ⇒ 这是**离我们最近的邻居**（同样是冻结主干 + 外挂记忆），且它给出了**可复现的负结果**：
     回退阈值若在"短上下文"上校准，部署到长上下文时**覆盖率从 0.88 崩到 0.31**。

## 2. 骨架五件套（沿用既有术语，不另起名字）

```
① 分层记忆体（L0/L1/L2）         —— 取代「全 KV 驻显存」
② 双通道激活（本地 / 远端召回）   —— 取代「近端窗口特权」
③ 可学习路由（indexer / 门控 / 块路由） —— 取代「固定稀疏模式」
④ 两速权重（慢：主干；快：测试时更新的神经记忆 + 低秩适配器）
⑤ 自进化（用户反馈驱动的记忆写入 → 静默期巩固 → 版本化主干升级）
```

**这五件的相互咬合方式**（这是本架构的"活"的地方）：
- 响应态：②的双通道在①的 L0 上取数，③决定取哪些页，④的快权重决定"怎么用"；
- 静默态：在①的 L1/L2 上做回放/重排/巩固，把"结论"写成**记忆条目**（不改主干）；
- 自进化：⑤把用户反馈变成**记忆写入的权重与遗忘的强度**（不是直接改主干权重）。

## 3. 概念迁移表（旧栈 → 新架构一等公民）

| 旧栈里的东西 | 在新架构里的身份 | 迁移动作 |
|---|---|---|
| KV cache | **记忆条目（可寻址、可稀疏取用）** | 从"计算的副产品"升为"存储的一等公民"，带写入/淘汰/热度 |
| attention 的窗口稀疏 | **双通道激活中的本地通道** | 滑窗固化为本地通道（便宜、保流畅） |
| Quest/SeerAttention/DSA 的页选择 | **远端召回通道** | 从"加速技巧"升为"信息通路"（近的没有特权） |
| MoE 路由 | **记忆块路由**（MoBA 式） | 从专家路由泛化到记忆块路由 |
| FFN | **记忆层 + 保留的少量 dense FFN** | Memory Layers 式替换（3 层甜点，共享记忆池） |
| MTP 头 | **快皮层的一部分** | 多头预测 → 顺带产出多条候选（加速与记忆共享一次前向） |
| 分级激活 / 热集驻留（TierAct） | **记忆页的热度与驻留调度** | 信号复用，不再是独立项目 |
| 静默态的回放/巩固 | **记忆写入与重排的执行期** | 从"上层设计"落为"存储层动作" |
| 自进化闭环（T12） | **记忆写入的强度与遗忘的门控** | 用户反馈 → 写入权重/遗忘率，而非直接改主干 |
| 快/慢权重（BioBrain 双轨 ≡ TTT） | **④ 两速权重** | 直接继承，作为架构的时标分离 |

## 6. 权重复用矩阵（**v3.2 起基于 Qwen3.8-27B 真实分解**）

**设计基准实测分解**（真 config 自算）：64 层 = **48 linear + 16 full**；d=5120；heads 24/4；head_dim 256；intermediate 17408。
每层 full（GQA+输出门）≈ **105 M**、每层 linear（Gated DeltaNet+门）≈ **84 M**、每层 MLP ≈ **267 M**；embed+head ≈ **2.54 B**；合计 **27.37 B**。
（旧 Qwen3-14B 的 62.9M/层 attn 与 267.4M/层 MLP 矩阵**作废**，见 §1A.5。）

| 组件 | 来源 | 处理方式 |
|---|---|---|
| Tokenizer + embed | Qwen3.8-27B | **直接搬运**（248320 词表，与 Qwen3.5/3.8 全系兼容） |
| LM head | Qwen3.8-27B | **直接搬运**（**与官方 MTP 头共享输出头**，不用自造） |
| **linear 层（Gated DeltaNet）定长态** | Qwen3.8-27B | **原样保留 + 视为天然可写记忆位**：48 层 × 3.0 M 态，不随序列增长 |
| **full 层 q/k/v/o（105 M/层）** | Qwen3.8-27B | **改造搬运**：本地通道直接用；远端通道 query 复用 q，k/v 低秩化为记忆条目编解码 |
| MLP / SwiGLU（267 M/层） | Qwen3.8-27B | **部分保留、部分替换**：按 Memory Layers 甜点替换少数层为共享记忆层，其余保 dense |
| 层数 / Norm / **mRoPE + 局部 RoPE(0.25)** | Qwen3.8-27B | **直接搬运**（结构等价改写；位置编码必须原样，否则长程外推失真） |

| ③ 记忆条目编解码（低秩 r=512） | **新增**：5.2 M/层 → 0.21 B；**跨层共享则仅 5.2 M** | 用 K/V 投影做低秩初始化（激活 PCA） |

（4bit 下分别约 +43 MB / +55 MB 权重，对 16–21 G 的底座仍可忽略）。

```

   新模块全部"零初始化/恒等挂载"
   （门控输出置零、LoRA 置零、记忆层暂时旁路）
   → 验收：**功能判据——全位置 logits max-abs-diff ≤ 1e-3**（教师强制、覆盖每一位）；
           逐 token 一致率仅作辅助（门槛取"确定性底线"）。
           ⚠️ v3.1 修订：**不再要求逐位相同**。理由（作者定调）：**本架构本身要自我进化**，
           权重会被写入/巩固/改写，"与原模型逐位一致"只是搬运旧参数的诊断工具，不是项目目标；
           且实测多挂一个模块会让 cuBLAS 选不同核 → ~1e-4 漂移、token 一致率在 79%–100% 摆动，
           这类核级漂移与"改造是否有功能副作用"无关。
S1 只训新架构件（**必须同时放开读出侧**）
   ★ 实测修正（N2c）：**只冻主干 + 只训记忆分支 ⇒ 召回 0%**。记忆要被"读出来"，
     下游层与 LM head 必须一起进入训练（末 K 层 LoRA + LM-head LoRA）。
   训练对象：路由打分器（自蒸馏）+ 门控 + 记忆编解码 **+ 读出侧（末 K 层 q/v LoRA + LM-head LoRA）**；
             主干其余部分仍冻结；数据：语料 + 自产轨迹 + 合成关联
   → 验收：**记忆召回**（训练键）显著高于「无记忆分支的纯读出侧对照」，且多种子同向；
          保留域无退化（六道闸）
S2 小步联合 + 记忆写入
   快皮层 LoRA 解冻（护栏杆）；开启静默期记忆写入（惊喜门控）
   → 验收：难例准确率 +3pp；复用率不降；swap 后双轴重校准通过
```

### 8.2 新增两条必须遵守的规则（实测血的教训）

1. **零初始化铁律**：**只允许"最后一层门"（gate）零初始化，门的输入侧必须非零**。
   实测：`gate=0` 且下游 `V=0`（或 `w_out=0`）时，`∂L/∂gate` 与 `∂L/∂V` **互相乘零 ⇒ 零死锁**，分支永远学不动；而且**等价性测试对这个 bug 是盲的**（它检验的正是"输出没变"）。
2. **init 梯度体检（必做，30 秒）**：改造完成后立刻打印 `∂L/∂gate` 与 `|∂L/∂w_out| / |∂L/∂V|`。
   - 若 `∂L/∂gate = 0` ⇒ 死锁，回去查初始化；
   - 若 `∂L/∂gate ≠ 0` 而 `∂L/∂w_out = 0` ⇒ **正常**（这是"先开门（gate 先动），再训分支"的顺序依赖），S1 阶段据此排序。

### 8.4 N2d/N2e 结账与路线分叉（2026-09-24，**重大定位修正**）

**实测结论（详见 `N2_报告.md` §6–§8）**：
- N2c 曾报"记忆分支 + 读出侧 = 9.4% 召回"，**放大到 128 键 × 2 种子后归零 ⇒ 那是 n=32 单种子的噪声**。
- N2d：记忆分支净贡献 **−1.0 pp**（无正贡献）；N2e（Titans 式**运行时动态写入**）：训练键/留出键 exact 召回 **0.0%**，loss 曲线不稳（4.73→8.30→3.54）⇒ **实现未过关**。
- **被否的假设**：「只训 0.3% 架构件 + 冻结主干」就能把知识写进记忆表。
- **对标提醒**：Memory Layers（1T token）与 Sparse Upcycling（~50% 原始预训练预算）都是**大规模联合训练**；业界**没有**"冻结主干 + 小模块"这个档位的成功先例 ⇒ **本项目的省算力期望必须下调**。
- **仍然稳定成立**：S0 严格无损（100%/0.0）；9 轮训练后主干张量 max-diff 全部 **0.000e+00**；工装可复用。

### 12A.1 轴一：上下文容量（目标：128K 可跑，且**每步不变慢**）

| 手段 | 具体做法 | 收益（算得出） | 本机 | 风险 |
|---|---|---|---|---|
| **L1 KV 量化** | `-ctk q8_0 -ctv q8_0` | 192→96 KiB/token，128K 从 24→12 GiB | ✅ 立即可做 | ⚠️ **不要用 q4 V**（实测相似度崩 8.3%；q4_0 的 99.9% 分位 KLD 比 q5_0 高 32%，PPL 掩盖尾部伤害） |
| **L2 驱逐/稀疏** | Quest / SeerAttention-R / DSA 式 indexer | 128K 每步读 20.5 GiB → 0.62 ms（top-4096） | ⚠️ 无 MSVC ⇒ **只能 PyTorch 支线** | 证据分散任务上静默崩（2607.13205）；H2O 让 leaf-value QA 精确匹配 88%→**0%** |

| **L4 架构替换（本项目的活）** | **记忆页替代远端 KV**：历史压成低秩条目（d=512），每 token 只读 top-k 页 | 128K 每步从 47 ms → **0.62 ms**；MLA 化则 128K KV 1.41 GiB | ⚠️ 需训练 | 校准必须在**部署长度区间**做（R13：短上下文校准 ⇒ 覆盖 0.88→0.31） |

**验收（可测）**：128K 上下文在 12 GB 上可跑；**decode tok/s 相对 8K 的下降 ≤ 30%**（同时盯"装得下"与"每步不变慢"）。

### 12A.1b ✅ 已实测验证的性能定律（N7/N8，2026-09-25）——**本机的第一条硬结论**

| 组 | KV 分配 | 真实上下文 | decode tok/s | 每 token |
|---|---|---|---|---|
| B | ctx 8192（不超额） | 0 | **44.0** | 22.7 ms |
| G | ctx 40960（超额） | 4K | 9.33 | 107 ms |
| C | ctx 40960（**超额 247 MiB**） | 16K | **4.73** | 211 ms |
| **Q1** | ctx 32768（**余量 617 MiB**） | **16K** | **25.5** | 39.2 ms |
| **Q4** | ctx 40960 + **末 8 层 FFN 下 CPU**（余量 762 MiB） | **32K** | **15.4** | 65 ms |

**Q4 细节**：真喂 **30,305 token**，prefill 平均 **48.8 tok/s**（10.4 分钟），decode **15.4 tok/s**。
**⇒ 32K 上下文在本机"可用"（15.4 tok/s），但未达验收线（相对 d0 只剩 0.35×，要求 ≥0.70×）——诚实记录不达标**，
要闭合只能靠架构手段（记忆页替代远端 KV）或 KV 再压，不是调参。

**另一个被暴露的瓶颈：prefill**。入 30K token 需 **10.4 分钟**（2K 时 226.8 tok/s → 30K 平均 48.8 tok/s）
⇒ 「装得下」之外还得治 **TTFT**（静默态预热 / 前缀缓存正是干这个的，见 T13）。

**定律（因果闭环）**：**同模型同内容，只把 KV 分配从"超额"改成"留余量"，decode 回升 5.4×（4.73 → 25.5）；
相对 d0 仅慢 1.7×，而不是 9.3× 崩盘。**
⇒ **本机铁律：`-c` 必须按 KV 预算留余量，绝不能"能塞多少塞多少"**（超额 247 MiB 就足以塌掉一个数量级）。

**KV 预算表（`--probe` 实测，只加载不推理，秒级）**
| 配置 | ctx | model | KV | compute | 合计 | 余量 |
|---|---|---|---|---|---|---|
| q8 KV | 32768 | 8148 | 3264 | 252 | 11665 | **+617** ✅ |
| q8 + 末 8 层 FFN 下 CPU | 32768 | 7115 | 3264 | 325 | 10704 | **+1578** ✅ |
| q8 + `-nkvo`（KV 放主机） | 32768 | 8148 | 0 | 320 | 8469 | **+3813** ✅ |
| K q8 / V q4 | 32768 | 8148 | 2496 | 252 | 10897 | +1385 ✅ |
| q8 KV | 40960 | 8148 | 4080 | 300 | 12529 | **−247** ❌ |
| f16 KV | 32768 | 8148 | 6144 | 195 | 14487 | −2205 ❌ |

**剩余差距的性质（才是"记忆页"要打的靶子）**：25.5 vs 44 的差 ≈ 16 ms/token 属于**16K 真上下文的
KV 读取 + 注意力计算本身**（KV q8 1.5 GiB/步 ÷ 504 GB/s ≈ 3 ms，其余为注意力与调度），
**与"显存超额"无关**。⇒ 架构要打的正是这 16 ms。

### 12A.1c ★★ 本机性能总规律（三档区间 + 配置菜单，全部实测）

| 组 | 配置 | **加载期余量** | prefill tok/s | decode tok/s |
|---|---|---|---|---|
| **Q6** | q8, ctx **24576**, 不卸载 | **1434** | **2202** | **37.8** |
| B | q8, ctx 8192 | ~3.8 GiB | 1038 | 44.0 |
| Q2 | q8, ctx 32768, 末 8 层 FFN 下 CPU | 1578 | 1538 | 19.5 |
| Q1 | q8, ctx 32768, 不卸载 | 617 | 73.1 | 25.5 |
| Q5 | 同 Q1 + 小批量 `-b 512 -ub 256` | 617 | 72.6（**无效**） | 26.9 |
| Q4 | q8, ctx 40960, `-ot` | 762 | 48.8 | 15.4 |
| C | q8, ctx 40960, 不卸载 | **−247（超额）** | —— | **4.73** |

**三档区间（由"加载期余量"单变量预测）**
| 区间 | 加载期余量 | prefill | decode |
|---|---|---|---|
| **健康区** | ≥ **1.4 GiB** | 1500–2200 tok/s | 37.8–44 |
| **悬崖区** | 0.6–0.8 GiB | **49–73（20–30× 塌）** | 15–25 |
| **灾难区** | 负（超额） | —— | **4.7** |

**四条铁律**
1. **改配置前先 `--probe`，把 `total` 压到 ≤10850 MiB（余量 ≥1.4 GiB）** ⇒ 同时买到快 prefill 与快 decode（Q6 首次达成）。
2. **`--probe` 只保证"能加载"，不保证"prefill 不溢出"** ⇒ 加载期余量才是 prefill 的判据。
3. **压小批量 `-b/-ub` 无效**（Q5 实测），别再试。
4. 换余量只有**两种货币**：少放权重（`-ot` 层下 CPU）或 少要 KV（收 `-c` / 压 V）。

**配置菜单（可直接抄）**
| 用途 | 命令要点 | 余量 | prefill | decode |
|---|---|---|---|---|
| **推荐日常（≤16K）** | `-c 24576 -ctk q8_0 -ctv q8_0` | 1434 | **2202** | **37.8** |
| 32K 长文低 TTFT | `-c 32768 … -ot "blk\.(4[0-7])\.ffn.*=CPU"` | 1578 | 1538 | 19.5 |
| 16K 会话 decode 优先 | `-c 32768 -ctk q8_0 -ctv q8_0` | 617 | 73 | 25.5 |
| ⛔ 绝不要 | `-c 40960` 不卸载 | −247 | —— | 4.7 |

**⇒ 对架构定位的意义**：**这 20–30× 的悬崖是"显存预算分配"问题，不是算法问题**。
先治预算（白拿 5.4×），**剩下那截（37.8→44 的差、32K 时的降幅）才是记忆页与写入门控的真战场** ——
这也解释了为什么"记忆页替代远端 KV"值得做：它换的正是**余量**（把 KV 从显存里请出去而不引入 PCIe 往返）。

| 项 | 值 |
|---|---|
| 头结构 | 1 层解码块 + `proj(2d→d)` + RMSNorm，共享 embed/lm_head，**327.7 M 参数** |
| 训练数据 | 本项目 `*.md`/`*.py`，**160 chunk × 512 token ≈ 82 K token**（隐状态预缓存） |
| 显存峰值 | **9.04 GiB**（cache 阶段仅 2.05 GiB） |
| **α₁（v1, lr 3e-4 恒定 600 步）** | 0.3396 |
| **α₁（v2, lr 1e-4+余弦 2000 步）** | **0.4445** |
| 平凡基线（复读） | 0.0111 ⇒ 头 **40× 于基线** |
| 判据 0.6 | **未达**（但已从"跑不通"推成"可迭代"） |

**关键教训**：v1→v2 **只改 lr 调度**（3e-4 恒定 → 1e-4+warmup+余弦）就 **+0.105 绝对**。
⇒ 与 N2e 同一条：**"实现未过关" ≠ "原理证伪"**，先怀疑超参再怀疑原理。

**为什么还差**：训练 loss 掉到 0.033（近乎背下 140 chunk），数据 82 K token vs 头 327 M 参数
⇒ **过拟合是主因**，下一刀是扩 cache（640 chunk）与缩小头。

**14B 在 PyTorch 侧的现实约束（重要，写进铁律）**：
本机 bnb 4bit/8bit 对 14B **必 segfault**（28 GB bf16 先落主机内存 ⇒ 爆 16 GB RAM；
在 Windows 上表现为 EXIT=139 而非 MemoryError）。**替代方案 = 逐层流式加载**
（`code/mtp_n8s1.py`，48 层 30.3 s，峰值 1.98 GiB；五条坑见 N8 报告）。

**天花板先算清**：Q4_K_M **8.37 GiB/步**的权重读取，504 GB/s ⇒ **理论 60 tok/s**（实测 56，已贴顶）。
⇒ **要提速只能"少读权重"或"一次读多产出"**，调参无效。

| 手段 | 做法 | 预期 | 本机 | 备注 |
|---|---|---|---|---|
| **S1 自训 MTP 头** ⭐ | 加 1 个 MTP 层（共享 embed/head）：attn 62.9 M + MLP 212.3 M ≈ **0.275 B**（Q4 ≈0.16 GiB） | 投机 α ≥60% ⇒ **1.5–2×** | ✅ 冻结主干只训头：bf16 头 0.55 G + Adam 1.1 G，可与 8.37 G 主干共存 | **本基底无 MTP 头 ⇒ 这是白拿增速的主路径**；DeepSeek-V3 已证明共享输出头可行（自造多头 5×1.45 GiB 会爆卡） |
| **S2 ngram / draft 投机** | llama.cpp `--spec-type ngram-mod`；或小 draft 模型 | 1.2–1.8×（依文本） | ✅ 立即 | 14B 是 dense ⇒ **无"混合循环回滚贵"问题**（R7 不适用） |
| **S3 记忆层替 FFN** ⭐ | 少数层 dense FFN → 乘积键记忆查表 | 每层每 token 访存 **127.5 MiB → 80 KiB（1632×）** | ⚠️ 需训练 | 这是本架构的架构级提速，也是 N6-③ 的形态换代目标 |
| **S4 KV 量化** | 见 12A.1 L1 | 长上下文时**顺带提速**（128K 每步 KV 读取 24→12 GiB） | ✅ | 越长越赚 |
| **S5 精度再压** | Q4_K_M → IQ4_XS / 或 FP8/NVFP4（需换卡） | 直接减 10–20% 读取 | ⚠️ | 先测质量再定 |

**验收**：短上下文 tok/s ≥ 1.5× 基线；128K 下每步耗时增幅 ≤30%；投机 α 与接受长度如实记录（不许只报最好一层）。

### 12A.3 轴三：自学习（目标：写入即生效、可审计、可回滚、不被自评污染）

**本基底给了 4 个物理落点**（从便宜到贵）：

| # | 落点 | 内容 | 是否改主干 | 本机可做 |
|---|---|---|---|---|
| 1 | **记忆表** | 关联条目（低秩 d=512，1 M ≈1 GiB）→ DRAM/盘 | ❌ 完全不改 | ✅ |
| 2 | **快皮层 LoRA** | r=16，挂 attn+MLP ⇒ 57.7 M（0.4%） | ✅ 局部 | ✅ |
| 3 | **MTP 头** | 提升自身接受率 + 可微调 | ✅ 新件 | ✅（与 S1 同一份参数） |
| 4 | **索引/提示缓存** | 静默期预热（`--cache-ram` + `--cache-idle-slots`） | ❌ | ✅ |

**闭环（沿用 T12，信号分级不变）**：用户行为当标注函数 LF → 弱监督标签模型输出概率标签 + 置信度 → 归因闸门**弃权优先** → 写入四池分账 → 静默期巩固 → 双轴评测（满意度/有效性**禁止合并成一个标量**）→ 可回滚。

**验收**：难例 +3pp；复用率不降；无灾难遗忘；跨长度区间一致（同 R13）；写入后主干 max-diff 仍为 **0**。

## 12B. 前沿思路调研（2026-09，全部实证取自 arXiv/OSDI/USENIX，附本机可行性）

> 起因：N7/N8 实测把真瓶颈钉成了「**权重 8148 MiB + KV 4080 MiB + compute 240 MiB > 物理 12282 MiB ⇒ 静默超额 ⇒ 每步走 PCIe ⇒ 解码崩 9×**」。
> 本节只收**能打到这个病**（以及三条轴）的前沿工作，并逐条标注本机能不能试。

### 12B.1 针对「显存不够 ⇒ 数据搬来搬去」这一层

| 工作 | 它做了什么 / 关键数字 | 对我们的意义 | 本机可试？ |
|---|---|---|---|
| **DirectKV**（OSDI'26, "No Buffer, No Bottleneck"） | 首次**零拷贝** KV 卸载：host-pinned memory 让 GPU 直接访存，不用 HBM staging buffer | **最硬的一条反直觉结论**：零拷贝在 **PCIe 上慢 20×（1122ms vs 56ms）**，但在 NVLink-C2C 上只慢 2×。⇒ **本机（PCIe）绝不能走"零拷贝直访主机内存"路线**；要么用**显式异步拷贝**（Swap 模式在 PCIe 只增加 <10% 开销），要么把注意力计算也下放 CPU | ✅ 可对照：`-nkvo`（KV 放主机）vs 显式拷贝路径 |
| **MMA**（arXiv 2512.16056v2） | **多路主机内存访问**：用 7 张 peer GPU 做中继，host→GPU 带宽 53→**245 GB/s（4.62×）**；单张卡时原生拷贝只能跑 ~53 GB/s | 单卡机用不上"中继"，但它指出 **PCIe 拷贝路径本身常常没跑满**（CUDA streams 把拷贝当单个有序任务）⇒ 我们的搬运优化空间在**并行流/预取**，不在硬件 | ⚠️ 部分（llama.cpp 内部，非用户可控） |
| **KVPR**（ACL Findings'25） | **I/O 感知的 KV 部分重算**：与其把 KV 从 CPU 拉回来，不如**直接重算** | 解码是带宽瓶颈、算力大量闲置 ⇒ **"重算代替搬运"** 在本机是可行的（我们 44 tok/s 时算力利用率很低） | ✅ 概念可测（对照：搬运 vs 重算） |
| **Unified KV Pooling**（arXiv 2606.14779） | 把多个主机内存模块 + SSD 聚合成**单一逻辑池**，按带宽分发 KV；指出 SSD 检索 84% 时间耗在**内核文件系统**而非设备 | 说明"KV 放盘"的真实瓶颈常在**软件栈**不在介质 | ⚠️ 需要改造运行时 |
| KV 管理综述（arXiv 2607.02574） | 把 KV 从"张量缓冲"升级为**分布式内存层级**；给出 HBM/主机 DRAM/CXL/RDMA/SSD 的容量-带宽-延迟-语义对照 | 我们的「分层记忆体 L0/L1/L2」正是这个框架的实例；可直接引用它的 tier 表 | ✅ 引用级 |
