# N1 · S0 结构等价改写 —— 实验报告
> 作者：Satyr_Astry　｜　日期：2026-09-24　｜　代码：`code/memstate_s0.py`（首版）、`code/memstate_s0b.py`（修正版）
> 结果 JSON：`code/s0_result.json`、`code/s0b_result.json`　｜　环境：`/e/HARNESS/selfgrow/venv`（torch 2.11+cu128），RTX 4070 Ti 12GB
> 被试模型：**Qwen2.5-1.5B-Instruct**（本机 HF 缓存已有，fp32，28 层 / d=1536）
> 目的：验证「忆态架构（MemState）」的 **S0 结构等价改写** 是否成立 —— 即**把现有模型的参数装进新骨架后，行为是否严格不变**。

---

## 0. 结论（三句话）

1. **S0 通过**：改写后 **逐 token 一致率 100.00%，logits 最大绝对差 0.000e+00**（逐位相同，非"近似"）。
2. **新分支是活的**：gate 抬到 1.0 → 输出改变（一致率 98.11%）；归零 → 恢复 100%（**可回滚**）。
3. **新分支可训**：冻结主干、只训记忆分支（gate + w_out + 记忆值 V）30 步，**loss 1.1818 → 0.7835**，gate 从 0 长到 ±0.062。

伴随两个**真实工程发现**（首版原型跑不通才是产出）：
- **发现 1（零死锁）**：`gate=0` 与下游 `V=0`（或 `w_out=0`）**同时存在**时，两侧梯度互相乘零 ⇒ 分支**永远学不动**，且**等价性测试仍会"假通过"**（因为它判的就是"输出没变"）。
- **发现 2（开门顺序）**：只有 `gate` 零初始化时，**启动瞬间梯度只流向 gate**，`w_out/V` 的梯度要等 gate 离开 0 才出现 ⇒ S1 的正确顺序是"先开门，再训分支"。

## 1. 实验设置

| 项 | 值 |
|---|---|
| 主干 | Qwen2.5-1.5B-Instruct，fp32，28 层，d=1536（1543.7M 参数，全冻结） |
| 改造点 | 3 层 MLP（**居中 stride 8 → 层 [10, 14, 18]**）→ `MemoryFFN = 原MLP + gate · 记忆输出`，**三层共享同一个记忆池**（Memory Layers 式） |
| 记忆层 | 乘积键 top-k 查表：半键 256×128 ×2 → **65536 条目**；每 token 取 **k=8**；值维度 d=1536 ⇒ 记忆池 **384 MiB**（fp32） |
| 其他新增 | 各层 q_proj 挂**零初始化 LoRA**（r=16）；路由打分器（DSA 式 indexer）每层一个（S0 只计算不生效） |
| 判据 | 4 条 prompt × greedy 48–66 token 的**逐 token 一致率** + 末位 logits 的**最大绝对差** |

## 2. 首版原型（`memstate_s0.py`）：等价通过，但**活性测试失败**

| 检查项 | 结果 | 判定 |
|---|---|---|
| S0 等价性 | 一致率 **100.00%**，logits 差 **0.000e+00** | ✅ |
| 活体（gate 0 → 0.05） | 输出**完全没变**（100%） | ❌ ← 本应变化 |
| 可训性（gate + w_out + LoRA-B） | loss 1.5659 → 1.0068 | ✅ 但**下降来自 LoRA**，gate 恒为 0.0000 |
| 回滚 | 100% | ✅ |

**根因定位**：首版把 `w_out` 与 `V` 都零初始化 → 记忆输出恒为 0 → `∂L/∂gate = ⟨∂L/∂out, 记忆输出⟩ = 0`，而 `∂L/∂V = gate · (...) = 0`。**两侧互为对方的零因子，形成零死锁（dead corner）**。
⇒ 更危险的是：**等价性测试对这个 bug 是"盲"的**（它检验的正是"输出没变"，死锁分支恰好满足）。

## 3. 修正版（`memstate_s0b.py`）：全部四项通过

### 3.1 修正设计（唯一正确形式）

```
只允许【最后一层门】零初始化：  gate = 0        ← 保证 S0 严格无损（gate·x ≡ 0 逐位为 0）
门的输入侧必须非零：            V, w_out, q_proj = 随机初始化
```
首轮修错（只改 w_out、留着 V=0）仍失败，**第二处零初始化才是真凶** → 说明"链条上任一零因子都会锁死"。

### 3.2 四项验收（实测）

| # | 检查 | 实测值 | 判定 |
|---|---|---|---|
| 1 | **S0 等价性**（gate=0） | 一致率 **100.00%**，logits 最大差 **0.000e+00** | ✅ 严格无损 |
| 2 | **死锁检测**（init 时梯度） | `∂L/∂gate = [2.497e-03, -2.249e-04, 3.026e-03]`；`|∂L/∂w_out| = 0`、`|∂L/∂V| = 0` | ✅ 死锁解除（且看清"gate 先动"的顺序） |
| 3 | **活性**（gate=1.0） | 1 条 prompt 输出改变，一致率降至 **98.11%** | ✅ 分支真在计算图里 |
| 4 | **回滚**（gate 归零） | 一致率 **100.00%** | ✅ 可瞬间回退 |

### 3.3 归因训练（单变量、可对照）

| 训练对象 | 可训参数 | loss 起点 → 终点 | Δ | gate 变化 |
|---|---|---|---|---|
| **只训记忆分支**（gate + w_out + V） | 7.77M（含 65536×1536 记忆值） | 1.1818 → **0.7835** | **−0.3983** | 0 → **±0.062** |
| **只训 LoRA**（冻结记忆分支） | ~0.2M/层 | 1.1818 → **0.1986** | −0.9832 | 0（未动） |

**读法（重要）**：两者都能学，但**刻度不同**——LoRA 改了 28 层的 q_proj，记忆分支只动了 3 层 + 一个从小长起来的门。这张表的意义是**归因干净**：以后任何 loss 下降都能分清是"主干适配"还是"记忆写入"的贡献（单变量纪律）。

### 3.4 资源与耗时

- 峰值显存 **8.36 GiB**（fp32 主干 6 GiB + 记忆池 384 MiB + 激活/梯度）
- 端到端 **31.3 s**（含模型加载 4 s）

## 4. 对本项目的意义（N1 闸门 = 通过）

1. **"基于现有参数造新架构"在结构上被证明可行且严格无损**：不是"看起来还在工作"，而是**逐位相同**；且装进来的新分支**活的、可训的、可回滚的**。
2. 原计划书写的一致性门槛是"≥98%"，**实测直接打到 100% + logits 差 0** → 门槛可以升级为：**同设备要求 100%（逐位）**；跨设备保留 ≥98%（浮点累加差异已在 TierAct 中实证）。
3. 首版的 bug 暴露了一条**必须写进规范**的初始化铁律（见下 §5），以及一条**新的必做检查**：**init 梯度体检**（打印 `∂L/∂gate`，30 秒可做，能挡掉数小时的无效训练）。

## 5. 归一化到 14B 的推论（规模换算）

| 项 | 1.5B 原型 | 14B 目标（Qwen3-14B，40 层 / d=5120） |
|---|---|---|
| 替换层 | 3/28（居中 stride 8） | 3/40（同规则，层 [16, 20, 24]） |
| 记忆池 fp32 | 65536×1536 = **384 MiB** | 65536×5120 = **1.34 GiB**（fp16 671 MiB / 低秩 d=512 仅 67 MiB） |
| 每 token 访存 | dense FFN ≈ 20160 KiB（Q4）vs 记忆查表 k=8 ≈ **24 KiB** → **840×** | dense FFN 127.5 MiB/层 vs 记忆 80 KiB/层 → **1632×** |
| 主干是否可训 | 全冻结（本机只能训 LoRA/架构件） | 同样：全参继续训练需 ≈474GB ❌ |

| 阶段 | 内容 | 关键风险 |
|---|---|---|
| N2 | 记忆**替换层选型**（stride/层数扫描）+ 路由打分器自蒸馏（让远端召回真的"看对地方"） | 判据错误 → 见 2607.13205 的崩法 |
| N3 | 记忆库分层放置（低秩 d=512 → DRAM 常驻；大池 → 盘 mmap）+ 查表内核（纯 PyTorch 起步） | 随机访存带宽 |
| N4 | 快皮层 + 静默期写入（惊喜门控） | 灾难遗忘 / 自噬 |
| N5 | 14B 上的 S0 复现（同一脚本、换模型）+ 与基线 GGUF 推理链对齐 | 本机显存（fp32 14B = 56GB ❌ → 需 bf16 分层加载或先在 8B 上做） |

*注：14B 的 S0 复现需要 fp32/bf16 权重（量化 GGUF 无法做逐位等价验证），本机需先解决"28GB 权重也放不进 12GB"的问题 —— 方案：分层加载 + 逐层比对（每层单独前向比对中间张量），列为 N5 的子任务。*
